# 测试后台的提案比例组件

原后台继续运行原镜像；demo 独立后台复用同一固定镜像及既有页面。
目前没有找到已部署 Rice 版后台的源码，公开默认分支仍为旧 Core 接口，不能拿来覆盖。

`patch-proposal.py 原bundle 输出bundle` 先检查原文件完整 SHA，再仅替换
`mOt` 提案配置组件。`proposal-percentage.js` 保留既有卡片、表单、编辑／取消／提交，
只改百分比输入，读取既有节点目录计算 `ceil(节点数 × 比例 / 100)`，提交原
`proposal_approval_votes` 字段；保存及结票仍用原票数逻辑，不新增后端字段、迁移或资格规则。
显示节点数和换算票数；重开页面显示已保存票数对应的百分比。不添加依赖，不修改其他组件或认证。
原文件或组件位置有变化就停止，不能跳过校验。生成产物须通过 `node --check`，
然后只挂载测试后台的单个 JS 文件，并仅重建 `admin-ui`。

这是已部署产物的有限补丁，不是完整后台源码。找回 Rice 版源码后，应将这一个组件
改动移回源码并正常构建；不得把补丁用于原生产后台而声称完成源码迁移。

节点稻米发放沿用同一测试后台：`patch-node-grant.py 已打提案补丁的bundle 输出bundle`
先检查已部署测试 JS 的 SHA，只增加“发放给节点”弹窗、节点发放 API 调用，以及
发放记录中的节点名称。它复用既有验证码，不向前端缓存或累加节点余额；发放成功后
从 Rice 重读余额。同一笔网络重试保留 `client_request_id`。
执行 `node test-node-grant.cjs` 和 `node --check 输出bundle` 后，仅替换测试后台
`admin-ui` 的 JS 挂载。原生产后台及旧 `main` 的 Core 源码不用于构建此产物。
